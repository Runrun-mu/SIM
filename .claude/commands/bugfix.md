# /bugfix — 自动 Bug 修复工具

你是一个自动化 bug 修复助手。请执行以下步骤：

## 步骤 1: 扫描 Bug 文件

使用 Glob 工具扫描 `bug/*.md` 获取所有 bug 报告文件。
注意：bug 文件位于当前项目根目录的 `bug/` 下。

## 步骤 2: 逐个分析每个 Bug 文件

对每个 `bug/*.md` 文件：
1. 使用 Read 工具读取文件内容
2. 检查文件中的状态字段（可能是 `**状态**`、`state：` 等格式）：
   - 如果状态包含 `已修复` 或 `✅` → **跳过**，计入「已修复」
   - 如果文件为空或无有效内容 → **跳过**，计入「空文件」
   - 如果状态为 `未修复`、`❌`、`🔍 待排查` 等 → **进入修复流程**

## 步骤 3: 修复未修复的 Bug

对每个未修复的 bug：

1. **分析错误描述**：仔细阅读 bug 文件中的错误描述（des 字段）、复现步骤、截图/日志
2. **查看截图**：如果 bug 文件引用了截图（如 `![alt text](image-1.png)`），使用 Read 工具查看 `bug/` 目录下对应的图片文件
3. **定位根因**：
   - 根据 bug 描述中提到的文件路径、错误信息，使用 Grep/Glob/Read 在代码库中搜索相关代码
   - 分析代码逻辑，找到导致 bug 的根本原因
4. **应用最小化修复**：
   - 只修改必要的代码，不做无关重构
   - 使用 Edit 工具精确修改目标代码
   - 确保修复不会引入新问题
5. **更新 Bug 文件**：在 bug 文件末尾追加修复记录：

```markdown
---

## 修复记录

**根因分析**: [简要描述根本原因]

**解决方案**: [描述修改了什么、为什么这样修改]

**修复时间**: [当前日期时间]

**修改文件**:
- `path/to/file1.ts` — [修改说明]

**状态**: ✅ 已修复
```

6. **将原始状态字段更新为已修复**

## 步骤 4: 输出汇总报告

最终输出格式：

```
═══════════════════════════════════
  🐛 Bug 修复汇总报告
═══════════════════════════════════
  📂 扫描文件数:   X
  ✅ 之前已修复:   X (跳过)
  📭 空文件:       X (跳过)
  🔧 本次修复:     X
  ❌ 修复失败:     X
═══════════════════════════════════
```

如果有修复失败的 bug，列出失败原因。

## 注意事项

- 修复时优先考虑**最小改动原则**
- 如果 bug 描述不够清晰无法定位根因，在 bug 文件中记录分析结果，状态改为 `🔍 需要更多信息`
- 不要修改测试文件来"修复"测试失败的 bug，应该修复实际代码
- 修复完成后确保相关代码的类型检查不会报错
- 如果 target 字段要求截图验证，在修复后提示用户手动验证
